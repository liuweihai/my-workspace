# 项目规划与落地推进指南 (Project Planner)

## 技能定位与核心原则
帮助用户将一个模糊的“项目点子”快速转化为**清晰、低成本、高确定性**的落地实施方案。
核心原则：
1. **先做减法，再做加法**：优先定义 MVP（最小可行性产品）边界，杜绝初期过度设计。
2. **资产复用，成本最小**：优先使用成熟开源方案、免费额度、现成模板，明确投入收益比。
3. **闭环交付，清单跟踪**：每次规划必须沉淀出可执行、可打勾的任务清单与追踪看板。

---

## 规划执行四步法

### 第一步：立项梳理（怎么开始、如何开始）
引导用户快速明确以下 4 个关键维度：
1. **核心价值与目标人群**：解决了谁的什么痛点？核心功能（Killer Feature）是什么？
2. **MVP 边界定义**：
   - **Must Have（首期必做）**：核心功能闭环，最简路径。
   - **Won't Have（首期坚决不做）**：次要功能、复杂运营后台、过度美化等，移入后续迭代。
3. **技术路线选型**：推荐最简单、最容易维护的技术组合（如：前端、后端、数据库、托管平台）。
4. **分阶段里程碑**：
   - **M1（原型与验证）**：跑通核心 API 或单一界面流程。
   - **M2（功能闭环）**：完成核心业务链路。
   - **M3（部署与交付）**：上线部署、配置域名与持久化。
   - **M4（优化与推广）**：监控、日志、体验调优。

---

### 第二步：资源准备清单（需要准备什么）
从 4 个层面整理详细准备清单，让用户一目了然：
1. **账号与云服务**：
   - 源码仓库（GitHub / Gitee）
   - 云服务器 / 无服务托管平台（Vercel, Cloudflare, 阿里云, 腾讯云, 本地 Mac mini 等）
   - 第三方 API 与密钥（OpenAI/Gemini API Key, 支付, 邮件, 短信等）
   - 域名与解析（如有对外访问需求）
2. **本地与部署环境**：
   - 运行时版本（Node.js, Python, Docker 等）
   - 本地数据库与缓存（PostgreSQL, SQLite, Redis 等）
3. **资产与资料**：
   - 参考设计风格 / 竞品链接
   - 初始数据源或数据集
4. **关键技术储备 / 预研点**：
   - 识别项目中可能存在的技术阻塞点（如长轮询、流式传输、特定硬件驱动等），提前列出验证方案。

---

### 第三步：投入评估（投入多少）
评估并向用户列出两张账单：
1. **时间与精力投入**：
   - 预估总周期（如：1 周 / 2 周 / 1 个月）
   - 每日/每周建议投入时间
   - 阶段任务工时拆解（开发 vs 调试 vs 部署）
2. **财务与成本投入**：
   - **0 元 / 免费起步方案（优先推荐）**：利用 Vercel / Cloudflare Pages / 现有服务器（如局域网 Mac mini）。
   - **基础月度开销**：服务器规格、API Token 预算、域名续费等。

---

### 第四步：生成交付物与进度追踪看板（结束清单）

每次完成项目规划后，必须在用户工作区的项目目录下（默认在 `projects/<项目名称>/`）创建或更新 **`PROJECT_PLAN.md`**：

```markdown
# [项目名称] 落地执行计划书

> 创建时间：YYYY-MM-DD | 状态：规划中 / 开发中 / 已上线
> 核心目标：一句话描述项目目标

## 一、MVP 范围与技术选型
- **目标用户**：...
- **核心闭环**：A ➜ B ➜ C
- **技术栈选型**：
  - 前端：...
  - 后端：...
  - 存储：...
  - 部署：...

## 二、前期准备清单 (Pre-flight Checklist)
- [ ] **代码仓库**：创建 GitHub 仓库
- [ ] **密钥与凭证**：准备 API Key / 环境变量
- [ ] **运行环境**：配置本地开发与依赖环境
- [ ] **域名/服务器**：...

## 三、投入预算与排期
| 阶段 / 里程碑 | 预期成果 | 预计工时/周期 | 状态 |
| :--- | :--- | :--- | :--- |
| **M1: 核心原型验证** | 跑通核心链路 Demo | 2~3 天 | 待开始 |
| **M2: 功能闭环开发** | 完善业务逻辑与基础 UI | 3~5 天 | 待开始 |
| **M3: 部署与上线** | 部署到服务器/云平台，配置域名 | 1~2 天 | 待开始 |
| **M4: 测试与验收** | 冒烟测试、错误处理、优化体验 | 1~2 天 | 待开始 |

- **预估成本**：免费方案 / 约 ¥XX/月

## 四、执行任务清单与当前进度
- [ ] **Step 1**: 项目脚手架初始化
- [ ] **Step 2**: 数据结构与接口定义
- [ ] **Step 3**: 核心功能开发
- [ ] **Step 4**: 异常捕获与容错处理
- [ ] **Step 5**: 编写使用说明与部署运行

## 五、规划总结与后续建议
- **关键风险点**：...
- **下一步行动**：第一步应该做什么
```

---

## 交互执行规范
1. **结构化引导**：如果用户想法还不明确，采用互动提问引导用户逐步澄清关键点（不一次性抛出太多问题，每次 2-3 个核心问题）。
2. **主动生成文档**：规划达成一致后，主动落盘生成 `PROJECT_PLAN.md`。
3. **后续跟进**：在以后的会话中，当用户针对该项目提问时，主动读取该文件，更新打勾项 `[x]` 并展示最新进度百分比。
