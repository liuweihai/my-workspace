# 代码审查流程

## 审查清单

按以下顺序逐项检查：

### 1. 🔒 安全性
- [ ] 无硬编码密钥、token 或密码
- [ ] 用户输入已做验证和清理
- [ ] SQL 查询使用参数化查询
- [ ] 敏感数据不输出到日志

### 2. ⚡ 性能
- [ ] 无 N+1 查询问题
- [ ] 大数据集有分页处理
- [ ] 无不必要的重复计算
- [ ] 异步操作正确使用 async/await

### 3. 📖 可读性
- [ ] 函数命名清晰表达意图
- [ ] 复杂逻辑有注释说明
- [ ] 函数长度合理（< 50 行）
- [ ] 没有魔法数字，使用常量

### 4. 🧪 测试
- [ ] 新功能有对应的单元测试
- [ ] 边界条件有覆盖
- [ ] 错误路径有测试
- [ ] 测试命名描述了预期行为

### 5. 🏗️ 架构
- [ ] 符合项目现有的设计模式
- [ ] 没有循环依赖
- [ ] 关注点分离合理
- [ ] 接口设计易于扩展

## 审查输出格式

```markdown
# 代码审查报告

## 总体评价
[优秀 / 良好 / 需改进 / 需重写]

## 发现的问题
### 🔴 严重（必须修复）
- ...

### 🟡 建议（推荐修复）
- ...

### 🟢 小问题（可选修复）
- ...

## 亮点
- [做得好的地方]

## 改进建议
- [具体的改进方向]
```

## 步骤

1. 读取用户指定的代码文件或 diff
2. 按审查清单逐项检查
3. 生成审查报告
4. 如有严重问题，提供修复代码建议

## 验证
- 确认所有审查维度都已覆盖
- 确认报告格式完整
