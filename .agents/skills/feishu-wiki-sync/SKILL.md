# 飞书知识库自动化沉淀与通知技能 (Feishu Wiki Sync)

> **本文档定位与作用**：定义整个工作区中将 Markdown 成果文档自动分类沉淀至飞书知识库的标准流程。所有 AI Agent 在生成具有持久价值的文档时，必须遵循本技能的标准规范进行归档与通知。

---

## 一、四大硬性交付准则

每次执行文档沉淀，必须严格遵循以下四条规则：

1. **强制中文命名**：
   - 知识库文档标题必须为易懂的中文（严禁使用英文缩写或未命名的文件名，如不要叫 `GEMINI`，要叫 `项目全局开发与协作规范`）。
2. **开头必须有说明**：
   - 任何文档开头第一段必须使用引用块 `>` 简明扼要说明：
     `> **本文档定位与作用**：一句话阐明本文档是做什么的 / 核心解决什么问题。`
3. **结构化目录分类归档**：
   - 严禁将文档直接散落在知识库根目录；
   - 必须指定对应分类目录（支持多级目录，如 `核心业务项目/流媒体同步`）；
   - 常见推荐分类：
     - `项目技术规范`：架构设计、编码规范、系统总览
     - `核心业务项目/流媒体同步`：音视频转码、多平台分发
     - `核心业务项目/公众号发文`：排版规范、草稿箱管理、群发方案
     - `自动化运行报告`：每日定时巡检报告、热点新闻汇总
     - `学习研究笔记`：新技术调研、读书笔记、思考复盘
4. **即时通知闭环**：
   - 同步完成后，必须调用飞书机器人向用户个人飞书私信发送卡片通知，并在此会话中主动呈现可点击的飞书直达链接。

---

## 二、标准调用命令与方法

当 Agent 编写完本地 Markdown 文件后，直接调用内置工具：

```bash
# 标准调用语法：
python3 tools/feishu_client.py <文件路径或文本> <分类目录名> [自定义中文标题]
```

### 场景示例

#### 场景 1：沉淀技术规范或架构设计
```bash
python3 tools/feishu_client.py docs/specs/architecture.md "项目技术规范" "用户认证系统架构设计方案"
```

#### 场景 2：沉淀核心业务项目文档（多级嵌套目录）
```bash
# 自动在「核心业务项目」下挂载「流媒体同步」
python3 tools/feishu_client.py docs/specs/media-sync/README.md "核心业务项目/流媒体同步" "流媒体多平台同步项目架构与实施方案"

# 自动在「核心业务项目」下挂载「公众号发文」
python3 tools/feishu_client.py docs/specs/wechat-mp/README.md "核心业务项目/公众号发文" "微信公众号自动化发文与排版方案"
```

#### 场景 3：沉淀每日定时任务报告
```bash
python3 tools/feishu_client.py reports/daily_summary.md "自动化运行报告" "每日自动化运行报告-2026-10-11"
```

#### 场景 4：沉淀一段快速备忘或学习思考（无需建文件）
```bash
python3 tools/feishu_client.py "React 19 Server Components 核心机制：1. 无需客户端打包..." "学习研究笔记" "React 19 服务端组件原理解析"
```

## 三、底层运行机制与防呆保障

1. **同名防重智能更新**：
   - 若目标分类目录下已存在同名标题的文档，脚本会**自动原地更新其正文内容**，绝不反复新建冗余节点；
2. **多级目录自动创建**：
   - 若传入的目录不存在（无论是单级还是 `父/子` 结构），脚本会自动在知识库中创建对应的文件夹节点；
3. **环境隔离与多机支持**：
   - 凭据统一从本地 `.env` 读取（包含 App ID, Secret, Space ID, User Open ID）；
   - 代码同步通过 GitHub（`git pull` / `git push`），Mac 与 Mac mini 完全解耦与对齐。
